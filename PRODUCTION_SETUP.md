# Production Setup Guide: College Bus Tracking System

This guide outlines the end-to-end instructions for deploying the College Bus Tracking native Android application and configuring the production Firebase backend on a **₹0/month budget (Spark Free Tier)**.

---

## 1. Application & Package Identification

The Android application is configured under:
- **Application ID / Package Name:** `com.college.bustracker`
- **Minimum SDK:** API 26 (Android 8.0 Oreo)
- **Target SDK:** API 34 (Android 14)
- **Architecture:** Jetpack Compose, MVVM, Kotlin Coroutines & Flow, Foreground Location Service, MapLibre/OpenStreetMap, Firebase RTDB + Firestore.

---

## 2. Authentication Architecture

The system enforces a strict zero-student-friction, role-isolated architecture:

1. **Student — NO LOGIN:**
   - Cold app start launches directly into `StudentHomeScreen`.
   - No login prompt, no student ID, no email, and no password.
   - Public read-only access to live bus tracking, route lists, stop sequences, and stop-filtered bus swap notices.
2. **Staff (Drivers & Admins) — ID + Password:**
   - Accessible via the "Staff Login" button in the student screen top bar.
   - The UI accepts only **Driver/Admin ID** and **Password** (zero email fields visible).
   - The client application internally maps the entered staff ID to an isolated namespace:
     ```text
     <staff_id>@collegebus.internal
     ```
   - Authenticated through standard Firebase Authentication (Email/Password provider).
   - Account status (`active == true`) and role privileges (`ADMIN` or `DRIVER`) are strictly validated against Firestore `/users/{uid}`.
   - Drivers are strictly bound to their assigned bus (`assignedBusId`). A driver cannot track, update, or report swaps for any other bus.

## 3. Production Firebase Setup (Manual Steps in Firebase Console)

### Step 3.1: Create Production Firebase Project
1. Navigate to the [Firebase Console](https://console.firebase.google.com).
2. Click **Add Project** (or **Create a project**).
3. Name your project (e.g. `college-bus-tracker-prod`).
4. **Google Analytics:** Disable Google Analytics to eliminate unnecessary background SDK telemetry and keep data usage strictly within zero-cost limits.
5. Click **Create Project** and ensure it is created on the **Spark Plan (Free)**.

### Step 3.2: Register Android Application
1. On the Firebase Project Overview screen, click the **Android** icon (`+ Add app`).
2. Enter the exact Package Name:
   ```text
   com.college.bustracker
   ```
3. Enter App Nickname: `College Bus Tracker Production`.
4. Enter your release signing **SHA-1 Fingerprint** (see Section 6 for generating your release keystore).
5. Click **Register App**.
6. Download the generated `google-services.json`.
7. Replace the development placeholder file in the repository:
   ```text
   app/google-services.json
   ```

### Step 3.3: Enable Firebase Authentication
1. In the Firebase console sidebar, navigate to **Build > Authentication**.
2. Click **Get Started**.
3. Under the **Sign-in method** tab:
   - Select **Email/Password**.
   - Enable the first toggle (**Email/Password**).
   - Leave *Email link (passwordless sign-in)* disabled.
   - Click **Save**.

### Step 3.4: Provision Production Staff Accounts
Under **Authentication > Users**, click **Add user** to create staff credentials. Use strong, unique passwords and the internal email format:

| Role | Staff ID in App UI | Firebase Auth Email | Password Requirement |
|---|---|---|---|
| System Admin | `[YOUR_ADMIN_ID]` | `[YOUR_ADMIN_ID]@collegebus.internal` | 16+ character strong password |
| Driver (Bus 1) | `[DRIVER_01_ID]` | `[DRIVER_01_ID]@collegebus.internal` | 12+ character strong password |
| Driver (Bus 2) | `[DRIVER_02_ID]` | `[DRIVER_02_ID]@collegebus.internal` | 12+ character strong password |

> [!IMPORTANT]
> Copy the unique **User UID** generated by Firebase Authentication for each staff account. You must use this exact UID as the Document ID in Firestore.

## 4. Cloud Firestore Setup & Security Rules

### Step 4.1: Create Firestore Database
1. In the sidebar, navigate to **Build > Firestore Database**.
2. Click **Create Database**.
3. Select your database region (e.g. `asia-south1` for Mumbai / India for lowest latency).
4. Select **Start in production mode** (default deny).
5. Click **Create**.

### Step 4.2: Deploy Security Rules
In the Firestore **Rules** tab, paste the rules from `backend/firestore.rules`:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Helper functions
    function isAuthenticated() {
      return request.auth != null;
    }
    
    function getUserData() {
      return get(/databases/$(database)/documents/users/$(request.auth.uid)).data;
    }
    
    function isUserActive() {
      return isAuthenticated() && getUserData().active == true;
    }
    
    function isAdmin() {
      return isUserActive() && getUserData().role == 'ADMIN';
    }
    
    function isDriver() {
      return isUserActive() && (getUserData().role == 'DRIVER' || getUserData().role == 'ADMIN');
    }

    function getDriverAssignedBusId() {
      return getUserData().assignedBusId;
    }

    // Users collection: users can read their own profile; admins can manage all
    match /users/{userId} {
      allow read: if isAuthenticated() && (request.auth.uid == userId || isAdmin());
      allow write: if isAdmin();
    }

    // Buses: Public read (Students have NO login); only Admins can create/edit/delete
    match /buses/{busId} {
      allow read: if true;
      allow write: if isAdmin();
    }

    // Routes & Stops: Public read (Students have NO login); only Admins can create/edit/delete
    match /routes/{routeId} {
      allow read: if true;
      allow write: if isAdmin();
    }

    // Bus Swaps: Public read (Students see swap notices without login);
    // Authenticated active drivers can ONLY report swaps for their assigned bus; admins manage all
    match /bus_swaps/{swapId} {
      allow read: if true;
      allow create: if isAdmin() || (
        isDriver() && 
        request.resource.data.driverId == request.auth.uid &&
        request.resource.data.originalBusId == getDriverAssignedBusId()
      );
      allow update, delete: if isAdmin() || (
        isDriver() && 
        resource.data.driverId == request.auth.uid &&
        resource.data.originalBusId == getDriverAssignedBusId()
      );
    }
  }
}
```
Click **Publish**.

## 5. Realtime Database Setup & Security Rules

### Step 5.1: Create Realtime Database
1. In the sidebar, navigate to **Build > Realtime Database**.
2. Click **Create Database**.
3. Select location (e.g. `Singapore (asia-southeast1)` or nearest available).
4. Select **Start in locked mode**.

### Step 5.2: Deploy RTDB Security Rules
In the RTDB **Rules** tab, paste the rules from `backend/database.rules.json`:

```json
{
  "rules": {
    "users": {
      "$uid": {
        ".read": "auth != null && (auth.uid == $uid || root.child('users').child(auth.uid).child('role').val() == 'ADMIN')",
        ".write": "auth != null && root.child('users').child(auth.uid).child('role').val() == 'ADMIN' && root.child('users').child(auth.uid).child('active').val() == true",
        ".validate": "newData.hasChildren(['role', 'active'])",
        "role": {
          ".validate": "newData.val() == 'ADMIN' || newData.val() == 'DRIVER'"
        },
        "active": {
          ".validate": "newData.isBoolean()"
        },
        "assignedBusId": {
          ".validate": "newData.val() == null || newData.isString()"
        }
      }
    },
    "live_locations": {
      ".read": true,
      "$busId": {
        ".write": "auth != null && root.child('users').child(auth.uid).child('active').val() == true && (root.child('users').child(auth.uid).child('role').val() == 'ADMIN' || (root.child('users').child(auth.uid).child('role').val() == 'DRIVER' && root.child('users').child(auth.uid).child('assignedBusId').val() == $busId))",
        ".validate": "newData.hasChildren(['busId', 'latitude', 'longitude', 'trackingStatus', 'lastUpdated']) && newData.child('busId').val() == $busId",
        "latitude": {
          ".validate": "newData.isNumber() && newData.val() >= -90 && newData.val() <= 90"
        },
        "longitude": {
          ".validate": "newData.isNumber() && newData.val() >= -180 && newData.val() <= 180"
        },
        "trackingStatus": {
          ".validate": "newData.val() == 'ACTIVE' || newData.val() == 'INACTIVE' || newData.val() == 'WAITING_FOR_GPS'"
        },
        "lastUpdated": {
          ".validate": "newData.isNumber()"
        }
      }
    }
  }
}
```
Click **Publish**.

### Step 5.3: Populate Initial Staff Profiles in Realtime Database
In Realtime Database **Data**, add the `/users` node with the staff user's **Firebase Auth UID**:

**Admin Node (`/users/{admin_auth_uid}`):**
```json
{
  "role": "ADMIN",
  "active": true,
  "customId": "[YOUR_ADMIN_ID]",
  "name": "System Transport Admin"
}
```

**Driver Node (`/users/{driver_auth_uid}`):**
```json
{
  "role": "DRIVER",
  "assignedBusId": "[PROD_BUS_ID]",
  "active": true,
  "customId": "[YOUR_DRIVER_ID]",
  "name": "Driver Full Name"
}
```

> [!NOTE]
> Storing staff authorization records under `/users` in Realtime Database enables RTDB security rules to validate that a driver is active and authorized ONLY for their assigned vehicle (`assignedBusId == $busId`) without relying on Firestore (which RTDB rules cannot read). When an Admin assigns a driver via the in-app Admin Console, the app automatically updates both Firestore and Realtime Database.

## 6. Release Keystore & Local Signing

Do NOT commit keystore files or passwords to source control. Follow this procedure on your local build machine:

### Step 6.1: Generate Local Production Keystore
Run `keytool` in a secure local directory outside the repository:

```bash
keytool -genkeypair -v \
  -keystore college-bus-release.jks \
  -alias college-bus-key \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000
```

To extract the SHA-1 fingerprint for Firebase registration:
```bash
keytool -list -v -keystore college-bus-release.jks -alias college-bus-key
```

### Step 6.2: Configure Signing Credentials via Environment Variables
Set the following environment variables on your build machine (or in `~/.gradle/gradle.properties`):

```bash
# In PowerShell:
$env:RELEASE_STORE_FILE="C:\path\to\college-bus-release.jks"
$env:RELEASE_STORE_PASSWORD="YourStrongKeystorePassword"
$env:RELEASE_KEY_ALIAS="college-bus-key"
$env:RELEASE_KEY_PASSWORD="YourStrongKeyPassword"
```

### Step 6.3: Build Signed Release APK & Bundle
```bash
# Build standalone minified Release APK:
./gradlew assembleRelease

# Build Google Play App Bundle (AAB):
./gradlew bundleRelease
```

Output locations:
- Release APK: `app/build/outputs/apk/release/app-release.apk`
- Release AAB: `app/build/outputs/bundle/release/app-release.aab`

## 7. Driver Device Hardware Configuration

For driver devices running foreground GPS tracking:

1. **Install Release APK:**
   ```bash
   adb install -r app/build/outputs/apk/release/app-release.apk
   ```
2. **Location Permission:**
   - In Android Settings > Apps > College Bus Tracker > Permissions > Location:
   - Select **"Allow all the time"** (enables background tracking when screen is locked).
3. **Battery Optimization Exemption:**
   - Android Settings > Apps > College Bus Tracker > Battery:
   - Select **"Unrestricted"** (prevents OEM aggressive background killers on Samsung, Xiaomi, OnePlus, Vivo).
4. **Notification Permission (Android 13+):**
   - Ensure Notifications are enabled so the Foreground Service persistent notification is displayed.
